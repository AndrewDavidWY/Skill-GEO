# GEO 结果测量

## 设计问题面板

按需要覆盖发现、定义、比较、使用场景、评估和品牌支持等真实受众问题。品牌问题与非
品牌问题分开。根据预算选择小规模面板，没有通用的问题数量或漏斗比例。记录问题原文、
稳定 ID、意图、语言、市场、引擎／产品、可获知的模型、检索模式、设置、日期和时区。

不得在每个问题中强塞品牌、向所谓自然可见度测试提供品牌页面，或要求模型推荐目标。
给定来源的实验可测试答案提取，但需与真实检索分开。`retrieval=off` 是闭卷回答，不能
证明当前搜索收录。

保留完整回答、展示的引用 URL，以及可获得的截图／导出。监测系统的回答数量不是消费
者搜索需求。使用新会话，在预算允许时重复观察；单次结果是抽查。失败和未知应记录，
不能当成负面回答。

## 结果定义

| 指标 | 分子 | 分母 | 不能证明什么 |
| --- | --- | --- | --- |
| 品牌提及率 | 明确识别目标实体的成功回答 | 提及标签已知的成功回答 | 推荐、引用或消费需求 |
| 推荐率 | 针对指定需求推荐目标的成功回答 | 推荐标签已知的成功回答 | 准确性或转化 |
| 官网引用率 | 至少展示一个自有域名引用的回答 | 引用列表已知的成功回答 | 被引来源支持每项主张 |
| 负面情绪率 | 对目标的负面评估 | 提及目标且情绪标签已知的回答 | 未经事实核查的产品缺陷 |
| 事实错误率 | 含已核验的目标相关事实错误的回答 | 提及目标且经过事实核查的回答 | 未核查回答的准确性 |

自有域名匹配包含其子域名；同一主机承载无关租户时应谨慎指定。第三方页面提及品牌是
外部佐证机会，不算官网引用。每个回答在每项指标只计一次，不重复计品牌别名或 URL。
人工解决实体歧义。提及和推荐标签针对回答正文，单有引用 URL 不自动设为 true。

如收集首位推荐、有证据支持的引用、声量份额、引荐会话和转化，分别定义单位和分母。
优先使用一组结果指标，不使用无法解释的合成总分。

## 随附离线工具

`scripts/score_visibility.py` 汇总**已经标注**的 JSONL 记录，仅用 Python 3.10+ 标准库，
不发网络请求。它不调用 AI 引擎、不发现引用、不核验事实、不自动识别品牌，也不复现
论文的位置加权字数／主观印象指标或 Promptwatch 分数。

从已安装的 skill 目录运行：

```bash
python3 scripts/score_visibility.py assets/sample-observations.jsonl --domain example.com
python3 scripts/score_visibility.py /path/to/observations.jsonl --domain brand.example --output /path/to/report.json
```

随附样本是模拟数据，不得作为品牌真实成效。输出包含每项指标的分子、分母、[0,1] 范围
内的率或 `null`、未知数量；还提供失败数、时间范围、问题次数，以及按引擎／模型／
语言／市场／检索模式分组的结果。总体率按回答汇总，不是均衡的模型或问题平均。
工具提示标签缺失和成功重复次数不均衡，跨期比较前先检查分组。

每个非空输入行是一个对象：

| 字段 | 格式／含义 |
| --- | --- |
| `run_id` | 唯一观察 ID；重复记录报错，不增加计数 |
| `prompt_id` | 对应已保存问题原文的稳定 ID |
| `engine`、`model`、`language`、`market` | 非空字符串；未披露模型用 `unknown` |
| `observed_at` | 带时区的 ISO 8601 时间，例如 `2026-10-09T09:00:00+07:00` |
| `retrieval` | `web`、`off`、`supplied` 或 `unknown` |
| `status` | `ok` 或 `error`；失败不进入结果分母 |
| `target_mentioned` | 布尔值；未标注用 `null` |
| `target_recommended` | 布尔值或 `null`；true 要求提及为 true |
| `cited_urls` | 展示的 HTTP(S) 引用字符串列表；确认没有用 `[]`，未知用 `null` |
| `sentiment` | `positive`、`neutral`、`negative`、`mixed` 或 `null`；仅目标被提及时标注 |
| `factual_error` | 核验后的布尔值，或 `null`；仅目标被提及时标注 |

成功记录必须包含全部五个标注字段，让缺失显式可见。失败记录可省略这些字段，或全部
设为 `null`。可增加 `response_path`、`prompt_text`、`intent`、`reviewer`、`source`、
`verification_notes` 等证据字段；工具不解读这些字段，原输入应保留以供审阅。
未经字段和单位映射，不能直接把供应商导出文件交给本工具。

## 比较与解释

比较相同问题、引擎、模型版本、市场、语言、检索模式、重复次数与等长时间窗口。组成
改变时比较交集或分别报告分组，不用混合汇总制造提升。失败／未知标签不进入相应分母，
披露覆盖率。从 20% 到 30% 应写**增加 10 个百分点**，或附基线的**相对增加 50%**；
基线为零时，相对变化无定义。

小规模重复面板不是用户的独立随机抽样。展示分子／分母、重复变异与缺失，不仅凭汇总
宣称统计显著。负面评估和事实错误需核验原始来源，不能只依据情绪分类器。

前后变化是观察。更强归因需要改变明确因素、尽可能保持匹配对照、记录部署和重新抓取
日期，并检查其他解释。引用、引荐、线索和收入可能不同步；referrer 丢失和未跟踪的
AI 使用会限制流量归因。
